## 0. Executive summary (the things most likely to change the plan)

1. **The pack already loads NeoForge 1.21.1 mods on Fabric via Sporran 1.0.7** (`sporran`, `provides: neoforge, kilt`). Pure-NeoForge jars in the pack: `L_Ender's Cataclysm 1.21.1-3.33.jar`, `astral_dimension-neoforge-1.21.1-3.0.jar`, `curios-neoforge-9.5.1+1.21.1.jar`, `lionfishapi-3.1.jar` (no `fabric.mod.json`, only NeoForge metadata). No Sinytra Connector is present (and Sporran explicitly breaks with it). Sporran bundles Porting Lib 3.1.0-beta.87 modules, a NeoForge event bus and a Global-Loot-Modifier layer. **=> the unmodified NeoForge DML jar might simply load in this pack. Worth testing before/in parallel with a native port.** (INFERRED; Sporran is "experimental, not every NeoForge mod works" per its CurseForge page.)
2. **AdventureZ (`adventurez-1.5.1.jar`) already implements a hatchable, rideable dragon from the vanilla dragon egg**: entity `adventurez:dragon` (has chest, `Dragon Saddle`, keybinds "Dragon Fly Down", "Dragon Fire Breath"), a mixin on `DragonEggBlock` that turns the vanilla egg into a block entity (`DragonEggEntity`) and a mixin in `ServerGamePacketListenerImpl.tick` that already prevents the flying-kick for its `DragonEntity`/`EnderWhaleEntity`. Config `adventurez.json5` has `allow_dragon_hatching: true`, `allow_other_dragon_hatching: false`, `heavy_dragon_flight: true`, `resummoned_ender_dragon_drops_egg: false`. This overlaps directly with the port's "vanilla dragon egg interaction" feature.
3. **The planned `ReplenishDragonEggMixin` (redirect inside `EndDragonFight.setDragonKilled`) would be dead code in this pack**: YUNG's Better End Island (`YungsBetterEndIsland-1.21.1-Fabric-3.1.2.jar`) injects at HEAD of `setDragonKilled`, re-implements the whole method and unconditionally calls `ci.cancel()` (verified with `javap`). Its own config already has `resummonedDragonDropsEgg = true` (config/betterendisland-fabric-1_21.toml) so eggs already replenish in this pack. Better End Remastered also injects `EndDragonFight.tryRespawn` HEAD + `EndPodiumFeature.place` HEAD.
4. **DML's `ModelPartMixin` is unnecessary on 1.21.1**: vanilla `ModelPart` already has public `xScale/yScale/zScale` (yarn `field_37938/39/40`); other mods in the pack read/write them directly (e.g. eternalstarlight `ESModelUtil`, verified with `javap`). Sodium 0.8.13 `@Overwrite`s `ModelPart.translateAndRotate` (`method_22703`) - exactly the method DML injects into - and rewrites `Cuboid`. Drop the mixin, use the public fields.
5. **Vanilla loot tables DML targets are largely bypassed in this pack** (YUNG's Better Desert Temples / Jungle Temples / Dungeons / Fortresses / Monuments / Witch Huts / Strongholds all have `disableVanilla...=true` or `removeVanillaDungeons=true`; DnT replaces the woodland mansion). Egg loot must target the replacement tables (section 4).
6. **Toolchain trap**: Loom 1.18+ is compiled for Java 25 (Gradle must run on JDK 25). The machine only has JDK 21 (Microsoft OpenJDK 21.0.10). Last Loom that runs on JDK 21 is **1.17.21**.

- Stay on the installed JDK 21: **Loom `1.17.21`** (plugin `net.fabricmc.fabric-loom-remap`) + **Gradle `9.5.0`** + Loader `0.19.5` + FAPI `0.116.17+1.21.1`.

## PART B - MODPACK COMPATIBILITY SCAN

### B0. How the scan was done / pack facts
- Every jar opened as a zip (nothing executed): `fabric.mod.json`, all mixin config JSONs, and a hand-written class-file parser extracted every `@Mixin` target + `@Inject/@Redirect/@WrapOperation/@ModifyExpressionValue...` target strings (6 871 mixin classes in 350 jars). Class IDs are **intermediary** (production). Some mods (Sporran, Debugify, Lithium, Sodium...) keep intermediary method ids (`method_xxxxx`), others have named (Mojang/yarn) strings resolved through a refmap. Where `javap` was needed it was run on extracted single classes only.
